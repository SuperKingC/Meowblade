# 《喵剑奇箱》Demo 运行说明

## 1. 当前交付状态

本工程已经完成一个可运行的玩法垂直切片，核心闭环为：

`猫宅自动生产 → 调整 3 只工人猫分工 → 治疗/补员/制作披风 → 3×2 编队 → 军团自动战斗 → 使用一次手动号令 → 胜利战损回城 → Boss 首通提高全局生产效率`

当前交付包含：

- 可直接进入 Play Mode 的 Unity 场景；
- 程序化 UGUI 猫宅主界面、编队界面、战斗界面和结算界面；
- JSON 存档、备份存档和 30 分钟离线生产；
- 普通关和 Boss 关；
- Windows 64 位可执行版本；
- 编辑器玩法自检和 Windows Player 启动冒烟测试。

当前定位是“功能与玩法完整的灰盒 Demo”。界面、猫猫、敌人和特效均使用程序化占位表现，尚未接入正式角色原画、Spine 动画、音效、音乐和商业化 UI 皮肤。

## 2. 推荐环境

- Unity：`2022.3.62f3`
- 场景：`Assets/Meowblade/Scenes/MeowbladeDemo.unity`
- 分辨率基准：`1920 × 1080`
- 屏幕方向：横屏
- 已验证 Player：Windows 64 位

### 2.1 Game 视图推荐分辨率

UI 的设计参考分辨率是 `1920 × 1080`，宽高比为 `16:9`。在 Unity Game 视图中选择 `1920×1080` 可以获得与设计稿完全一致的构图。

以下 16:9 分辨率也可以完整等比体验：

- `1280 × 720`
- `1600 × 900`
- `1920 × 1080`（设计基准，最推荐）
- `2560 × 1440`
- `3840 × 2160`

Canvas 使用 `Scale With Screen Size`，宽高匹配值为 `0.5`。因此 16:9 下布局比例一致；18:9、19.5:9 和 20:9 设备也能运行，但会比设计基准多出横向显示区域，正式美术背景需要准备左右延展区和安全区。

场景中已经包含 `Main Camera`，运行时 `AppBootstrap` 还会执行一次相机检查：如果场景没有相机，会自动创建并启用一台主相机。如果已经打开的场景仍显示旧的“No cameras rendering”，请关闭后重新打开 `MeowbladeDemo.unity`，或执行 `Assets → Refresh`，让 Unity 重新载入磁盘上的场景版本。

本次已实际启动验证：`1280×720`、`1920×1080`、`2560×1440` 和 `2340×1080`，四种分辨率均通过相机、主界面、编队和战斗界面冒烟测试。

## 3. 直接运行 Windows Demo

可执行文件：

`Builds/Windows/MeowbladeDemo.exe`

运行时必须保留同目录下的以下内容：

- `MeowbladeDemo_Data/`
- `MonoBleedingEdge/`
- `UnityPlayer.dll`

不要只复制单独的 `.exe` 文件，否则 Unity Player 无法启动。

## 4. 在 Unity Editor 中运行

1. 使用 Unity `2022.3.62f3` 打开工程根目录。
2. 等待右下角脚本编译和资源导入完成。
3. 打开 `Assets/Meowblade/Scenes/MeowbladeDemo.unity`。
4. 确认 Hierarchy 中存在：
   - `Main Camera`
   - `MeowbladeBootstrap`
5. 点击 Play。

运行时界面完全由 `AppBootstrap` 和 UI 工厂创建，因此场景中不需要预制大量 Canvas 节点。

## 5. 推荐试玩流程

### 5.1 猫宅主界面

进入后先观察顶部三种资源：

- 纸板：治疗、补员、制作披风；
- 鱼干：治疗和补员；
- 奇箱零件：制作披风。

三种资源会根据当前工人分配持续自动生产并直接进入仓库，不需要反复点击领取。仓库满后，对应工位会停止生产并显示满仓状态。

点击分工区域调整三类岗位上的工人数量。三个岗位分配总数不能超过 3；少于 3 时，剩余猫猫会显示为空闲工人。

建议首次试玩把工人从 `1/1/1` 调整为 `2/1/0` 或 `3/0/0`，观察纸板每分钟产量和岗位状态立即变化。

### 5.2 猫窝与工坊

猫窝提供：

- 治疗一只受伤小猫：`2 纸板 + 3 鱼干`；
- 补充一个空缺编制：`4 纸板 + 6 鱼干`。

奇箱工坊在普通关首通后解锁纸箱侠披风：

- 制作成本：`8 纸板 + 3 奇箱零件`；
- 效果：纸箱侠军团最终受到伤害降低 `20%`。

### 5.3 编队

点击“出战”进入 3×2 编队界面。

阵型规则：

- 左列为后排；
- 右列为前排；
- 建议纸箱侠放在前排；
- 小鱼干和毛线球放在后排；
- 先点击主将卡，再点击目标格即可交换位置。

普通关首次进入时，默认阵型已经可以通关，玩家仍可通过换位观察前后排规则差异。

### 5.4 战斗

战斗采用横向轻军团自动战斗：

- 主将和每只可用小猫都是独立战斗单位；
- 单位会自动移动、索敌、普攻和释放主将技能；
- 小猫倒下会在胜利后转为受伤；
- 主将倒下时，其所属军团撤退；
- 失败不会把临时战损写回猫宅。

唯一的手动操作是“全军钻箱”：

- 伤害和承伤会积累号令能量；
- 能量达到 100 后可使用一次；
- 使用后全军获得 4 秒、35% 的伤害减免；
- Boss 显示“箱盖重压预警”时使用效果最佳。

右下角可切换 `1×/2×` 战斗速度，也可以主动撤退。

### 5.5 完整闭环

推荐按照以下顺序验证：

1. 在猫宅观察资源生产；
2. 调整工人分工；
3. 补满纸箱侠最后一个小猫编制；
4. 进入普通关并获胜；
5. 回猫宅治疗受伤小猫；
6. 制作并装备纸箱侠披风；
7. 重新补满三支军团；
8. 挑战纸箱小霸王；
9. 在箱盖重压预警时使用“全军钻箱”；
10. 胜利后返回猫宅，确认猫宅等级变为 2，生产倍率由 `100%` 提高到 `130%`。

## 6. 存档与重置

游戏会在以下时机保存：

- 初始化完成；
- 调整工人分工；
- 治疗、补员或制作；
- 战斗胜利提交；
- 每 30 秒自动保存；
- 应用暂停或退出。

Windows Player 默认存档位置：

`%USERPROFILE%\AppData\LocalLow\Meowblade Studio\喵剑奇箱 Demo\meowblade_demo_save.json`

同目录可能存在 `.bak` 备份文件。一般测试不需要手动删除文件，主界面右上角“重置”按钮可以安全恢复 Demo 初始状态。

## 8. 关键代码目录

```text
Assets/
├─ Meowblade/
│  └─ Scenes/
│     └─ MeowbladeDemo.unity
└─ Scripts/
   ├─ Runtime/
   │  ├─ Meowblade.Runtime.asmdef
   │  ├─ Core/
   │  │  └─ GameDomain.cs
   │  ├─ Application/
   │  │  ├─ GameContext.cs
   │  │  └─ GameSession.cs
   │  ├─ Infrastructure/
   │  │  └─ Persistence/
   │  │     └─ JsonSaveRepository.cs
   │  ├─ Gameplay/
   │  │  └─ Battle/
   │  │     └─ BattleSimulation.cs
   │  └─ Presentation/
   │     └─ UI/
   │        ├─ AppBootstrap.cs
   │        ├─ UiFactory.cs
   │        ├─ HomeScreen.cs
   │        └─ BattleScreens.cs
   └─ Editor/
      ├─ Meowblade.Editor.asmdef
      └─ ProjectTools.cs
```

架构职责：

- `Core`：枚举、存档 DTO、显示规格、平衡数值和静态配置；
- `Application`：应用组合根、会话、时钟与存档接口；
- `Infrastructure`：JSON 文件存档、临时文件和备份文件实现；
- `GameSession`：生产、库存、工人、治疗、补员、制作和关卡状态，不直接依赖具体文件路径；
- `BattleSimulation`：与表现层解耦的确定性战斗模拟；
- `Presentation`：只负责读取会话/战斗状态和生成可交互表现；
- `Editor`：场景生成、Build Settings 配置和领域自检。

更完整的依赖规则、扩展方向和分辨率规范见 `喵剑奇箱_工程架构与分辨率规范.md`。
