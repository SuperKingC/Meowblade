## 0. 文档定位与版本口径

本文件用于指导《喵剑奇箱》第一版可玩 Demo 的玩法、界面、数值、程序结构和开发验收。

本文件吸收了原完整设计文档中的猫猫军团、行为装备、纸箱主题等内容，并结合《放置军团》APK 静态分析结果，将 Demo 核心从：

```text
自动推关 → 开箱 → 换装
```

调整为：

```text
猫宅生产 → 工人调度 → 补员/制作 → 军团出战
→ 小猫受伤 → 回宅恢复 → 首通提高生产 → 再次出战
```

版本优先级：

- 本文件是 **Demo 阶段的最高优先级玩法与实现口径**；
- `喵剑奇箱_完整设计文档_v1.1_优化版.docx` 继续作为长期内容池和后续版本参考；
- 若两份文档在 Demo 范围、主界面结构、资源、战损、开箱频率等方面存在冲突，以本文件为准；
- 本文件不代表正式上线版本已经确定，Demo 完成后必须根据试玩数据决定是否扩展。

## 1. 产品结论

### 1.1 一句话概念

玩家经营一间会持续运作的猫宅，将有限的工人猫分配到纸板、鱼干和奇箱零件岗位，用产物恢复小猫兵、制作行为装备，再率领三支猫猫小军团挑战纸箱敌人；每次突破都会让猫宅生产得更快、更热闹。

### 1.2 核心差异

本 Demo 不以“开箱抽装备”作为第一驱动力，而以“看得见的猫宅生产”和“战斗后的回城处理”作为第一驱动力。

玩家最常进行的核心行为是：

1. 观察猫猫在什么岗位工作；
2. 判断当前缺纸板、鱼干还是奇箱零件；
3. 重新分配有限的工人猫；
4. 补充或治疗小猫兵；
5. 制作能够针对 Boss 机制的行为装备；
6. 调整三支军团的位置；
7. 观看战斗结果并处理战后状态；
8. 通过首通永久提高猫宅生产效率。

### 1.3 Demo 必须验证的问题

| 验证问题 | 成立标准 |
|---|---|
| 看猫猫工作本身是否有趣 | 玩家进入后 10 秒内能理解三个岗位的差异，并愿意观察猫行为 |
| 工人调度是否形成选择 | 移走一只猫会让一个岗位变快、另一个岗位变慢，玩家能解释取舍 |
| 资源生产是否服务战斗 | 玩家会主动为了治疗、补员或制作装备而调整生产方向 |
| 战斗是否反向推动生产 | 战后产生受伤、配方解锁或产量提升，玩家自然返回猫宅处理 |
| 阵型和装备是否有效 | Boss 战前后调整的结果肉眼可见，而不是只增加一个战力数字 |
| 首通是否带来长期正反馈 | Boss 首通回城后，产量数字、工作速度和场景外观同时升级 |

### 1.4 Demo 暂时不验证的内容

- 长期付费和广告；
- 复杂开箱概率；
- 大规模装备池；
- 多章节和长期数值膨胀；
- 好友、公会、PVP；
- 永久角色损失；
- 数小时建筑升级；
- 多层中间材料生产链；
- 服务器权威经济与反作弊；
- 超过 30 分钟的离线经营平衡。

## 2. 核心循环

### 2.1 完整循环

```text
观察猫宅当前状态
    ↓
查看库存、岗位产量和受伤小猫
    ↓
调整 3 只工人猫的岗位
    ↓
等待并自动获得纸板、鱼干、奇箱零件
    ↓
治疗小猫 / 补充编制 / 制作行为装备
    ↓
配置 3 支军团的位置和装备
    ↓
进入自动战斗并选择一次军团号令时机
    ↓
胜利：提交小猫受伤、发放奖励、解锁进度
失败：不扣资源，返回调整
    ↓
首通永久提高生产倍率或解锁配方
    ↓
返回猫宅，立即看到生产和场景变化
```

### 2.2 30 秒短循环

```text
观察资源变化
→ 点击岗位查看产量
→ 调整一只工人猫
→ 确认新的每分钟产量
→ 看猫从旧岗位跑到新岗位
```

### 2.3 2～3 分钟中循环

```text
积累一轮材料
→ 治疗或补充小猫
→ 制作一件行为装备
→ 调整阵型
→ 挑战一关
→ 回城处理战后状态
```

### 2.4 6～8 分钟 Demo 循环

```text
学习生产
→ 第一次调度
→ 第一次补员
→ 第一关胜利并出现伤员
→ 回城治疗并制作装备
→ Boss 战调整与突破
→ 全局生产速度 +30%
→ 回城看到猫宅升级
```

## 4. 主界面：猫宅资源生产玩法

## 4.1 主界面目标

主界面必须同时承担以下职责：

- 展示资源正在持续生产；
- 让玩家看懂每只工人猫的岗位；
- 暴露缺料、满仓、无人工作等问题；
- 提供工人调度入口；
- 提供治疗、补员和行为装备制作入口；
- 展示当前主线关卡和 Boss 目标；
- 让战斗首通后的成长在场景中可见。

主界面不能只是功能按钮集合。即使玩家不点击任何按钮，也应该能看到猫猫走动、工作、搬运和休息。

## 4.2 主界面布局

Demo 使用单屏横向猫宅，不做复杂的大地图滚动。参考分辨率为 `1920×1080`，适配时以安全区和 Canvas Scaler 处理。

```text
┌──────────────────────────────────────────────────────────────┐
│ 纸板 18/60 +12/m │ 鱼干 13/50 +10/m │ 零件 4/30 +6/m │ 设置 │
├──────────────┬───────────────────────────────────┬───────────┤
│ 当前关卡     │                                   │ 猫窝      │
│ 普通关 1     │ 纸箱回收角  小鱼干厨房  奇箱拆解台 │ 受伤 0    │
│ Boss 预告    │ 猫工作、搬运、等待、睡觉的主场景   │ 治疗/补员 │
│ 推荐提示     │                                   │ 奇箱工坊  │
├──────────────┴───────────────────────────────────┴───────────┤
│ 猫宅 │ 分工 │ 军团 │             出战             │ 工坊 │
└──────────────────────────────────────────────────────────────┘
```

界面层级：

1. 顶部资源栏；
2. 中央猫宅生产场景；
3. 左侧关卡目标卡；
4. 右侧猫窝和奇箱工坊快捷入口；
5. 底部主功能栏；
6. 弹出的分工、猫窝、工坊和军团面板。

## 4.3 三种资源

### 4.3.1 纸板

定位：高频基础资源。

主要用途：

- 补充空缺小猫兵；
- 治疗受伤小猫；
- 制作纸箱类防御装备；
- 后续版本用于猫宅建筑升级。

场景表现：

- 完成品是一捆纸板或小纸箱；
- 工人猫会抓挠、撕胶带、压平纸箱；
- 交付时把纸板拖向中央仓库；
- 满仓时纸箱堆积并挡住部分工位。

### 4.3.2 鱼干

定位：治疗与兵员恢复资源。

主要用途：

- 治疗受伤小猫；
- 补充新的小猫兵；
- 后续版本用于主将猫成长和技能训练。

场景表现：

- 完成品是一碗或一串鱼干；
- 工人猫会推碗、闻鱼干、短暂偷吃；
- 交付时把鱼干放进带锁的小柜子；
- 满仓时柜门关不上，并显示鱼干图标气泡。

### 4.3.3 奇箱零件

定位：低频行为装备资源。

主要用途：

- 制作会改变战斗行为或表现的装备；
- 后续版本用于解锁新工位、特殊机关和箱子能力。

场景表现：

- 完成品为齿轮、弹簧、铃铛和神秘碎片；
- 工人猫会拨齿轮、追弹簧、拍亮按钮；
- 交付时把零件放进透明玻璃罐；
- 满仓时罐子闪光，猫会盯着零件发呆。

## 4.4 在线生产规则

在线时，资源由生产逻辑自动结算并自动进入库存，不要求玩家反复点击领取。

一次完整表现流程：

```text
工人猫前往工位
→ 播放工作动作
→ 生产进度完成
→ 生成一份资源包表现
→ 工人猫搬运到仓库
→ 库存数字增加
→ 飘字显示 +1
→ 工人猫返回工位开始下一轮
```

重要规则：

- 逻辑资源在生产周期完成时结算；
- 搬运动画只负责表现，不决定资源是否产生；
- 动画被跳过、暂停或切换场景时，生产逻辑仍然正确；
- 玩家点击场景中的资源包可以触发额外粒子和音效，但不重复增加资源；
- 当库存达到上限时，岗位停止结算并进入 `WaitingStorage`；
- 玩家消耗资源后，岗位自动恢复生产。

## 4.5 生产公式

单个岗位的实际生产速度：

```text
实际产量/分钟
= 单猫基础产量
× 分配工人猫数量
× 岗位等级倍率
× 全局关卡倍率
× 临时增益倍率
```

Demo 初始：

```text
岗位等级倍率 = 1.0
全局关卡倍率 = 1.0
临时增益倍率 = 1.0
```

Boss 首通后：

```text
全局关卡倍率 = 1.3
```

例如 Boss 首通后，一只纸板工人猫的产量：

```text
12 × 1 × 1.0 × 1.3 × 1.0
= 15.6 纸板/分钟
```

程序内部不使用每分钟整数跳变，而使用浮点生产进度：

```text
Progress += DeltaTime × RatePerSecond
```

当 `Progress >= 1` 时：

1. 计算可结算的整数数量；
2. 根据库存剩余空间截断；
3. 增加库存；
4. 扣除已经结算的进度；
5. 若库存已满，切换为满仓状态。

## 4.6 工人猫分配规则

### 4.6.1 总量限制

```text
纸板工人 + 鱼干工人 + 零件工人 + 空闲工人 = 3
```

每个岗位允许分配 `0～3` 只工人猫。

允许极端配置：

```text
纸板 3 / 鱼干 0 / 零件 0
```

这种配置会让纸板快速增长，但鱼干和零件完全停止，形成明确取舍。

### 4.6.2 分工面板

点击底部“分工”或任意生产岗位，打开统一分工面板。

```text
┌────────────────────────────────────────────┐
│ 猫猫分工                         可用猫 0/3 │
├────────────────────────────────────────────┤
│ 纸箱回收角   [-] 猫猫猫 [+]   12 → 24/分钟 │
│ 小鱼干厨房   [-] 猫     [+]   10 → 10/分钟 │
│ 奇箱拆解台   [-]       [+]    6 → 0/分钟   │
├────────────────────────────────────────────┤
│       恢复原配置       确认分工             │
└────────────────────────────────────────────┘
```

操作规则：

- 打开面板时复制当前正式配置为 `DraftAllocation`；
- `+` 和 `-` 只修改草稿；
- 每次修改立即刷新三个岗位的旧产量和新产量；
- 草稿总人数超过 3 时禁止继续增加；
- 点击“恢复原配置”放弃草稿改动；
- 点击关闭且草稿有变化时，弹出“放弃本次分工调整？”；
- 点击“确认分工”后进行一次原子提交；
- 提交成功后，场景中的工人猫从旧岗位跑到新岗位；
- 提交时自动保存。

### 4.6.3 空闲工人

如果总分配少于 3，剩余工人进入中央休息垫：

- 睡觉；
- 舔毛；
- 看其他猫工作；
- 头顶显示“空闲”小图标。

空闲工人不产生资源，但必须在分工面板中清楚显示，防止玩家误以为工人消失。

## 4.7 工人表现状态机

每只工人猫的表现状态：

```text
IdleAtHome          在休息垫空闲
WalkingToStation    前往岗位
Working             工作
CarryingProduct     搬运产品
Delivering          入库
Returning           返回岗位
WaitingStorage      满仓等待
ChangingJob         换岗移动
```

Demo 中猫的“偷吃、钻箱、玩弹簧、舔毛”等性格动作属于表现层微动作，不改变真实平均产量，避免玩家无法理解产量为什么波动。

后续版本可以增加明确标记的效率状态：

- 猫薄荷兴奋：短时间 2 倍；
- 偷懒：短时间停止；
- 好心情：一定时间工作加速。

但这些效率状态不进入第一版 Demo。

## 4.8 岗位状态与气泡

| 状态 | 条件 | 场景表现 | UI 文案 |
|---|---|---|---|
| Producing | 有工人且库存未满 | 正常工作和搬运 | `生产中：12/分钟` |
| NoWorker | 工人数为 0 | 工位落灰，无猫工作 | `未分配猫猫` |
| WaitingStorage | 对应资源达到上限 | 工人停在仓库旁，显示满箱 | `仓库已满 60/60` |
| Locked | 岗位未解锁 | 工位被布遮住 | `通关指定关卡解锁` |
| Paused | 系统暂停或进入结算 | 工人保持安全待机 | `暂停中` |

三个岗位在 Demo 中不消耗上游材料，因此不需要 `WaitingMaterial`。等后续加入多层生产链时再扩展。

## 4.9 库存和满仓

顶部资源栏始终显示：

```text
当前数量 / 上限
当前每分钟产量
```

例如：

```text
纸板 54/60  +24/分钟
```

当库存达到 80%：

- 数字变为黄色；
- 对应场景堆料明显增加。

当库存达到 100%：

- 数字变为橙红色；
- 显示 `已满`；
- 对应岗位停止；
- 工人显示满仓气泡；
- 点击资源栏打开用途提示，告诉玩家可以在哪里消耗。

Demo 不允许资源溢出为负数，也不允许超出上限后隐藏累积。

## 4.10 猫窝：治疗与补员

猫窝是生产与战斗之间最直接的连接点。

### 4.10.1 小猫状态

```text
Empty       编制空缺
Ready       可以出战
Injured     战斗中受伤，不能出战
Treating    正在播放治疗表现
```

### 4.10.2 治疗受伤小猫

```text
治疗 1 只受伤小猫
= 2 纸板 + 3 鱼干
```

表现：

1. 玩家选择受伤小猫；
2. 原子扣除资源；
3. 播放 2～3 秒包扎、喂鱼干或钻猫窝动画；
4. 状态从 `Injured` 变为 `Ready`；
5. 小猫从猫窝跑回对应主将身边。

Demo 不设置数分钟治疗队列，避免等待打断闭环。

### 4.10.3 补充空缺小猫

```text
补充 1 只新小猫兵
= 4 纸板 + 6 鱼干
```

表现：

1. 玩家选择有空缺的军团；
2. 扣除纸板和鱼干；
3. 猫窝中的纸箱晃动；
4. 一只新小猫跳出；
5. 该军团 `ReadyCount +1`。

补员和治疗必须在文案、图标和价格上区分：治疗更便宜，补充空缺更贵。

### 4.10.4 一键治疗

如果有多只受伤小猫，显示“一键治疗”。

- 先计算总费用；
- 资源不足时，不进行部分扣费；
- 可以显示“最多可治疗 X 只”，但 Demo 默认战损不超过 2 只；
- 一键治疗提交成功后逐只播放短动画，但逻辑一次性完成。

## 4.11 奇箱工坊：行为装备制作

## 4.12 离线生产

### 4.12.1 规则

```text
有效离线秒数
= Clamp(当前 UTC 时间 - 上次保存 UTC 时间, 0, 1800)
```

最大离线时间为 30 分钟。

每个岗位的离线产量：

```text
离线产量
= 有效离线秒数
× 保存时工人数
× 单猫每秒产量
× 保存时全局生产倍率
```

离线结算只处理：

- 纸板；
- 鱼干；
- 奇箱零件。

离线期间不处理：

- 自动治疗；
- 自动补员；
- 自动制作装备；
- 自动挑战新关卡；
- 自动通关 Boss。

### 4.12.2 库存上限

离线产量同样受到库存上限限制。

例如：

```text
离线理论获得纸板 80
当前纸板 20
上限 60
实际获得 40
因满仓损失 40
```

回归面板必须显示：

```text
离开时间：12 分 34 秒
纸板 +40（已满）
鱼干 +21
奇箱零件 +12
```

离线结果在进入主界面时立即原子应用并保存，面板按钮使用“收下”而不是“领取”，避免关闭应用导致重复或丢失。

### 4.12.3 时间异常

- 时间倒退：按 0 秒处理；
- 时间前跳：最多按 30 分钟处理；
- 本地 Demo 不实现联网校时；
- 日志记录异常时间差，便于测试。

## 5. 战斗界面：轻军团玩法

## 5.1 战斗定位

战斗采用横向 2D 实时自动战斗。

玩家的主要决策发生在战前：

- 哪三支军团出战；
- 每支军团放在前排还是后排；
- 当前小猫编制是否完整；
- 是否存在受伤小猫；
- 纸箱侠是否装备针对 Boss 的披风。

战斗中保留一个轻量手动操作：

> 军团号令“全军钻箱”。

这样既保留放置军团的自动观战感，又让玩家在 Boss 大招前有一次可理解的时机选择。

## 5.2 战斗前编队界面

点击主界面“出战”后先进入编队界面，不直接开始战斗。

```text
┌────────────────────────────────────────────────────────────┐
│ 普通关 1 / 纸箱小霸王       推荐：前排防御、范围控制         │
├───────────────────────┬────────────────────────────────────┤
│ 我方 3×2 阵型          │ 敌方预览                           │
│ [后上] [前上]          │ 敌人图标、数量、技能标签           │
│ [后中] [前中]          │ Boss：箱盖重压                     │
│ [后下] [前下]          │ 提示：主要攻击前排                 │
├───────────────────────┴────────────────────────────────────┤
│ 纸箱侠 2/3  披风✓ │ 小鱼干 3/3 │ 毛线球 2/2 │ 开始战斗      │
└────────────────────────────────────────────────────────────┘
```

编队操作：

- 拖动军团卡到任意空格；
- 同一格只能放一支军团；
- 一支军团包含主将猫和其小猫兵；
- 受伤小猫不进入战场；
- 编制不满时允许出战，但显示黄色警告；
- 主将猫不能空缺；
- 点击军团卡打开详情和装备；
- 点击敌人可以查看机制说明；
- 开始战斗前保存阵型。

推荐初始阵型：

```text
后排上：小鱼干
前排中：纸箱侠
后排下：毛线球
```

## 5.3 3×2 阵型规则

阵型共有 6 个逻辑位置：

```text
BackTop       FrontTop
BackMiddle    FrontMiddle
BackBottom    FrontBottom
```

Demo 上阵 3 支军团，因此必须选择其中 3 个位置。

位置影响：

- 前排军团优先被普通近战敌人锁定；
- 后排军团在前排存活时不被普通近战优先攻击；
- 远程敌人可以攻击后排；
- Boss“箱盖重压”主要命中前排，并对同一横线后排造成 40% 溅射；
- 军团所在位置决定入场点和初始寻路距离；
- 位置本身不提供隐藏的攻击或防御百分比，所有差异来自目标规则和技能范围。

## 5.4 军团组成

每支军团由：

```text
1 名主将猫
+ 2～3 只小猫兵
```

组成。

主将猫：

- 决定职业、主动技能、被动和装备；
- 主将生命归零时，该军团撤退；
- 主将不会永久受伤或丢失；
- 失败后恢复到战前状态。

小猫兵：

- 每只作为独立战斗实体显示和受击；
- 生命归零时钻入纸箱并退出本场战斗；
- 胜利结算时，生命归零的小猫变为 `Injured`；
- 失败时不提交小猫受伤，恢复战前状态；
- 小猫数量减少会降低该军团攻击频率和视觉规模。

## 5.6 基础伤害公式

```text
基础伤害
= Max(1, 攻击方 ATK × 技能倍率 - 防守方 DEF × 0.45)
```

```text
最终伤害
= 基础伤害
× 暴击倍率
× 伤害加成
× 伤害减免
× 随机浮动
```

其中：

```text
随机浮动 = 0.95～1.05
```

纸箱侠披风的 `-20%` 属于最终伤害减免，乘区为 `0.8`。

护盾先于 HP 承受伤害。

Demo 不加入：

- 命中；
- 闪避；
- 元素抗性；
- 韧性；
- 吸血；
- 多层增伤区；
- 复杂控制抵抗。

## 5.7 寻敌规则

### 普通近战单位

1. 优先同一横线最近的前排敌人；
2. 同一横线无目标时，选择距离最近的其他前排；
3. 所有前排撤退后，攻击最近后排；
4. 保持当前目标，除非目标死亡、撤退或不可达。

### 远程单位

1. 按技能配置选择目标；
2. 普通远程默认选择距离最近的有效目标；
3. 不频繁切换低生命目标，避免战场抖动。

### 纸箱侠

1. 优先拦截正在接近后排的敌人；
2. 否则攻击最近敌人；
3. 嘲讽成功后被嘲讽敌人强制以纸箱侠为目标。

### 小鱼干

- 普攻保持当前目标；
- 技能释放时搜索生命比例最低的可攻击敌人。

### 毛线球

- 普攻保持当前目标；
- 技能寻找能命中最多敌人的区域中心；
- 同样命中数量时优先覆盖 Boss。

## 5.8 战斗状态机

```text
Loading
→ FormationReady
→ Countdown
→ Running
→ Victory 或 Defeat
→ Settling
→ ReturnHome
```

具体流程：

1. 读取关卡配置；
2. 从保存数据创建 `BattleSnapshot`；
3. 根据阵型生成主将和 Ready 小猫；
4. 生成敌人和波次；
5. 1 秒准备倒计时；
6. 开始自动寻敌、移动、普攻和技能循环；
7. 玩家可以控制一次军团号令时机；
8. 清空全部波次则胜利；
9. 所有主将撤退或超时则失败；
10. 胜利提交奖励和小猫受伤；
11. 失败丢弃战斗副本，不扣资源、不提交伤员；
12. 返回结算或编队界面。

## 5.9 军团号令：全军钻箱

战斗界面右下角显示军团号令按钮。

能量获取：

```text
EnergyGain
= 我方造成伤害 × 0.05
+ 我方受到伤害 × 0.10
```

能量上限：`100`。

每场战斗最多主动使用一次。

效果：

```text
全军受到的最终伤害 -35%
持续 4 秒
```

表现：

- 所有猫短暂钻入纸箱或举起小纸箱盾；
- 屏幕边缘出现纸板护盾；
- Boss 大招预警颜色由红转黄；
- 持续期间受击产生纸屑特效。

自动模式：

- 玩家可以打开“号令自动释放”；
- 自动释放条件为能量已满且任意主将生命低于 50%；
- 默认关闭，以便 Demo 展示一次主动时机判断；
- 普通关可以不使用；
- Boss“箱盖重压”预警期间使用最有效。

## 5.12 Boss 关设计：纸箱小霸王

目标：验证补员、行为装备、阵型和军团号令能共同改变结果。

### Boss 基础属性

| 属性 | 数值 |
|---|---:|
| HP | 5000 |
| ATK | 48 |
| DEF | 18 |
| 攻击间隔 | 1.6 秒 |
| 移动速度 | 慢 |
| 时间上限 | 60 秒 |

### Boss 技能

#### 普通拍击

- 攻击当前前排目标；
- 造成 `1.0 × ATK` 伤害；
- 主要用于持续消耗纸箱侠。

#### 箱盖重压

```text
冷却：10 秒
预警：1.5 秒
```

效果：

- 对所有前排单位造成 `1.8 × ATK` 伤害；
- 对同一横线后排单位造成 40% 溅射伤害；
- 对小猫兵额外造成 10% 伤害；
- 可以通过“全军钻箱”明显降低伤害；
- 纸箱侠披风可以进一步降低前排军团伤害。

#### 呼叫纸箱鼠

```text
触发：Boss 生命首次低于 50%
效果：召唤 2 只纸箱鼠，从上、下两侧进入
```

设计目的：

- 让毛线球的范围减速产生价值；
- 避免所有输出只无脑打 Boss；
- 让后排位置和前排存活产生可见差异。

### Boss 难度目标

- 初始缺编制且没有披风时，胜率较低但不是脚本必败；
- 补满小猫、装备披风、纸箱侠放前排后，胜率明显提高；
- 在箱盖重压预警时释放号令，应该比随意释放少损失 1～2 只小猫；
- 玩家应能通过战斗表现理解失败原因；
- 失败结算最多显示两个建议，不显示长篇教程。

### Boss 首通奖励

```text
全局生产倍率：1.0 → 1.3
鱼干 +12
猫宅二级外观
第四只工人猫剪影预告
```

重复挑战奖励：Demo 中仅提供少量鱼干，不重复提高生产倍率。

## 5.13 胜负与战损提交

### 胜利

胜利时：

1. 统计本场生命归零的小猫；
2. 将对应小猫状态改为 `Injured`；
3. 主将猫恢复为可出战状态；
4. 发放普通奖励；
5. 检查是否首次通关；
6. 首通奖励使用唯一关卡 ID 幂等发放；
7. 保存；
8. 显示结算。

### 失败

失败时：

- 不扣除纸板、鱼干或零件；
- 不提交小猫受伤；
- 不降低关卡进度；
- 不重复发放任何奖励；
- 恢复到战前编制状态；
- 停止自动重试；
- 显示一至两个失败原因和对应入口。

失败建议示例：

| 检测结果 | 提示 | 快捷入口 |
|---|---|---|
| 前排在 15 秒内撤退 | `前排承伤不足` | 打开纸箱侠装备 |
| 有空缺或受伤小猫 | `军团编制不完整` | 打开猫窝 |
| 披风已解锁但未装备 | `纸箱侠可以装备披风` | 打开工坊/装备 |
| 号令未使用 | `Boss 重压时可以使用全军钻箱` | 返回挑战 |
| 超时且存活单位较多 | `输出不足` | 调整小鱼干位置或补员 |

## 6. 主城与战斗的双向连接

## 6.1 主城对战斗的影响

| 主城行为 | 战斗影响 |
|---|---|
| 生产纸板 | 提供治疗、补员和防御装备材料 |
| 生产鱼干 | 提供治疗和补员材料 |
| 生产奇箱零件 | 制作行为装备 |
| 调整工人猫 | 改变玩家解决当前战斗问题的等待时间 |
| 治疗受伤小猫 | 恢复军团实际人数和攻击频率 |
| 补充空缺小猫 | 提高军团完整度 |
| 制作披风 | 降低 Boss 前排伤害 |

## 6.2 战斗对主城的影响

| 战斗结果 | 主城影响 |
|---|---|
| 普通关胜利 | 产生受伤小猫，解锁工坊配方，获得零件 |
| Boss 失败 | 不扣资源，但提示返回治疗、制作或调阵型 |
| Boss 首通 | 永久提高所有基础资源产量 30%，升级猫宅外观 |
| 重复胜利 | 仅提供少量资源，不重复首通加成 |

## 6.3 闭环硬性要求

任何一场关键战斗后，至少发生一项主城动作：

- 治疗；
- 补员；
- 制作；
- 调度；
- 查看产量升级。

任何一项主城关键动作，都必须能够影响：

- 下一场战斗可用小猫数量；
- 军团生存；
- 军团输出；
- 或等待时间。

不允许出现主城生产和战斗各自运行、互不影响的情况。

## 11. 逻辑服务拆分

## 11.1 InventoryService

职责：

- 查询数量和容量；
- 增加资源；
- 原子消耗多种资源；
- 应用容量截断；
- 返回实际增加量和溢出量；
- 记录变更原因。

核心接口示意：

```csharp
public interface IInventoryService
{
    int GetAmount(ResourceId id);
    int GetCapacity(ResourceId id);
    bool CanAfford(IReadOnlyList<ResourceCost> costs);
    SpendResult TrySpend(IReadOnlyList<ResourceCost> costs, ChangeReason reason);
    AddResult Add(ResourceId id, int amount, ChangeReason reason);
}
```

`TrySpend` 必须先校验全部资源，再一次性扣除，不能出现纸板扣了但鱼干不足的部分交易。

## 11.2 WorkerAllocationService

职责：

- 查询正式分配；
- 创建草稿；
- 验证单岗位和总人数；
- 计算分配前后产量；
- 原子提交分工；
- 输出变更事件。

## 11.3 ProductionService

职责：

- 固定逻辑 Tick；
- 根据分工计算产量；
- 推进小数进度；
- 写入库存；
- 判断满仓；
- 输出岗位状态；
- 应用全局生产倍率。

逻辑 Tick 建议为 `0.2 秒`，即每秒 5 次。视觉层可以每帧插值，不需要每帧修改库存。

伪代码：

```csharp
void Tick(float deltaTime)
{
    foreach (var station in stations)
    {
        int workers = allocation.GetWorkers(station.Id);

        if (workers <= 0)
        {
            SetState(station.Id, WorkstationState.NoWorker);
            continue;
        }

        if (inventory.IsFull(station.OutputResource))
        {
            SetState(station.Id, WorkstationState.WaitingStorage);
            continue;
        }

        float ratePerSecond = CalculateRatePerSecond(station, workers);
        progress[station.Id] += deltaTime * ratePerSecond;

        int wholeUnits = FloorToInt(progress[station.Id]);
        if (wholeUnits <= 0)
            continue;

        AddResult result = inventory.Add(
            station.OutputResource,
            wholeUnits,
            ChangeReason.OnlineProduction);

        progress[station.Id] -= result.AddedAmount;
        SetState(station.Id,
            result.OverflowAmount > 0
                ? WorkstationState.WaitingStorage
                : WorkstationState.Producing);
    }
}
```

注意：如果只从进度中扣除 `AddedAmount`，满仓时剩余整数进度可能无限堆积。实现时应明确策略：

- Demo 推荐在满仓时把进度最多保留到 `0.999`；
- 不允许满仓期间暗中累积，消耗资源后瞬间爆出大量产物；
- 因此库存写入后，将进度截断到 `[0, 0.999]`。

## 13. 表现层实现

## 13.1 WorkerVisualController

每只工人猫持有：

```text
WorkerId
CurrentStationId
VisualState
Animator
PathAgent 或路径点引用
CarriedProductVisual
SpeechBubble
```

岗位改变时：

1. 收到 `WorkerAllocationChanged`；
2. 根据旧、新岗位数量决定哪只猫换岗；
3. 播放 `ChangingJob`；
4. 到达新岗位后进入 `Working`；
5. 即使移动动画未完成，逻辑产量也已经按正式配置生效；
6. 表现层不得反向增加资源。

## 13.2 产品搬运表现

逻辑每产生一个资源时，不一定生成一个完整搬运动画，否则高倍率下会过密。

建议：

- 逻辑记录一段时间内的生产次数；
- 视觉层按岗位速率播放循环搬运；
- 低速时一份资源对应一次搬运；
- 高速时一捆资源代表多份产物；
- 飘字可以显示 `+2`、`+3`；
- 生产倍率改变时调整动画频率，而不是强制逐单位表现。

## 13.3 BattleUnitView

职责：

- 读取逻辑实体位置和朝向；
- 播放移动、攻击、受击、技能和撤退；
- 显示 HP、护盾和状态；
- 生成投射物与特效；
- 不决定伤害命中时间。

伤害由逻辑层根据攻击事件结算，动画事件只用于对齐表现。如果动画丢失事件，逻辑仍然完成伤害。

## 13.4 对象池

需要对象池化：

- 小猫兵；
- 普通敌人；

## 15. 测试方案

## 15.1 EditMode 单元测试

### 库存

- 添加资源不超过容量；
- 满仓返回正确溢出量；
- 多资源消费具有原子性；
- 资源不足时不产生部分扣费；
- 容量为 0 时安全处理。

### 工人分配

- 总人数不超过 3；
- 单岗位不超过 3；
- 允许 3/0/0；
- 非法配置不能提交；
- 产量预览与正式计算一致。

### 在线生产

- 1 名纸板工人 60 秒产生约 12 纸板；
- 2 名纸板工人 60 秒产生约 24 纸板；
- Boss 首通倍率后产量为 1.3 倍；
- 满仓期间不暗中累积整数产物；
- 消耗资源后生产自动恢复。

### 离线生产

- 负时间按 0 处理；
- 超过 30 分钟按 30 分钟处理；
- 使用保存时的分工；
- 使用保存时的生产倍率；
- 正确处理满仓与溢出；
- 同一离线时间不会重复结算。

### 猫窝与制作

- 治疗成本正确；
- 补员成本正确；
- Injured 才能治疗；
- Empty 才能补员；
- 唯一装备不会重复制作；
- 未解锁配方不能制作。

### 战斗结果

- 胜利提交小猫受伤；
- 失败不提交受伤；
- 失败不扣资源；
- 首通奖励只发一次；
- Boss 生产倍率只应用一次；
- 相同结算 ID 重复提交不会重复发奖。

## 15.2 PlayMode 测试

- 调整分工后猫正确换岗；
- 切换场景后生产进度继续正确；
- 满仓气泡出现，消耗后消失；
- 猫窝治疗动画与逻辑状态一致；
- 披风制作后主界面和战斗外观都改变；
- 编队拖动和位置保存正确；
- 1×/2× 不改变战斗结果的规则正确性；
- Boss 预警和号令可见；
- 战斗返回后小猫状态正确；
- Boss 首通回城时场景升级一次。

## 15.3 手工体验测试

- 新玩家是否在 10 秒内看懂猫在生产；
- 是否知道为什么某岗位停止；
- 是否理解工人总数只有 3；

- Boss 首通回城后是否感到明显成长。

## 17. Definition of Done

只有满足以下条件，Demo 才算完成：

### 主界面

- 三个岗位均能独立生产；
- 总工人猫严格限制为 3；
- 分工前能预览产量变化；
- 确认分工后，数据和猫换岗表现同步；
- 在线生产不依赖动画完成；
- 满仓会停止生产并给出可理解反馈；
- 离线 30 分钟内计算正确；
- 猫窝能治疗和补员；
- 工坊能制作并装备纸箱侠披风。

### 战斗

- 三支军团能在 3×2 阵型中自由配置；
- 每支军团显示主将和实际 Ready 小猫；
- 普攻、技能、寻敌和死亡规则稳定；
- 普通关包含两波；
- Boss 包含重压预警和 50% 召唤；
- 军团号令能由玩家主动释放；
- 胜利提交战损；
- 失败不扣资源、不提交战损；
- 首通奖励幂等。

### 闭环

- 第一关后出现治疗、补员或制作行为；
- 披风和阵型能明显改善 Boss 战；
- Boss 首通后生产倍率从 1.0 变为 1.3；
- 回猫宅后能看到产量数字、工人节奏和场景外观升级；
- 从开始到完整闭环控制在 6～8 分钟；
- 流程中不存在超过 15 秒且没有观察价值或决策的纯等待。

## 18. 风险与控制方案

| 风险 | 表现 | 控制方案 |
|---|---|---|
| 主界面像动态背景 | 猫在动，但调度没有意义 | 总工人严格限制，产量和等待时间即时变化 |
| 资源种类仍然太多 | 玩家记不住用途 | Demo 只保留纸板、鱼干、零件三种 |
| 生产等待拖慢 Demo | 玩家无事可做 | 使用分钟级高产量，初始资源保证 30～60 秒内可操作 |
| 战斗看不懂 | 单位、数字和特效过多 | 只做 3 主将、最多 8 小猫、控制伤害数字频率 |
| 战损造成负面情绪 | 玩家认为猫死了 | 使用受伤、钻箱撤退、回猫窝治疗包装 |
| 失败后资源耗尽 | 玩家无法继续尝试 | 失败不提交战损、不扣资源 |
| Boss 像纯战力墙 | 调整没有用 | 重压有预警，披风、阵型、号令都能明确克制 |
| 动画驱动逻辑导致错账 | 切场景、倍速时漏产或重复 | 生产和战斗逻辑独立于动画回调 |
| 首通奖励重复 | 反复进入结算叠加倍率 | ClearedStageIds + 唯一结算 ID 幂等校验 |
| 文档范围再次膨胀 | 开始加入大量箱子和装备 | 第一版只做 1 件行为装备、2 个关卡、3 个岗位 |

## 19. Demo 后的扩展顺序

只有核心闭环验证成立后，再按以下顺序扩展：

1. 第四只工人猫和岗位容量选择；
2. 第二件、第三件行为装备；
3. 资源特化关卡奖励；
4. 猫宅建筑手动升级；
5. 更多主将猫和军团组合；
6. 后排突袭、治疗和远程敌人；
7. 2～3 个章节；
8. 30 分钟以上离线容量与仓库升级；
9. 宝箱作为定向奖励，而不是第一主循环；
10. 再评估广告、活动和长期经济。

暂不扩展：

- 永久小猫死亡；
- 工人租赁；
- 好友工人；
- 复杂随机偷懒惩罚；
- 多层中间材料；
- 15 个生产槽；
- 12 格阵型；
- 数十件随机装备；
- 装备洗练和升星；
- 公会和 PVP。

## 20. 最终执行口径

第一版 Demo 的核心不是“做一个功能很多的放置游戏”，而是把以下四个瞬间做到足够清楚：

1. 玩家把一只工人猫从零件台调到纸板区，纸板立即变快、零件立即停止；
2. 玩家用生产出来的纸板和鱼干，让一只小猫从猫窝跑回军团；
3. 玩家给纸箱侠装备披风并调整到前排，Boss 重压的结果明显改变；
4. 玩家击败 Boss 回到猫宅，看到所有猫工作得更快，整个家也更热闹。

如果这四个瞬间成立，后续的宝箱、装备池、章节、猫种和建筑都可以自然扩展。

如果这四个瞬间不成立，应先调整生产节奏、场景反馈、战损包装和 Boss 克制关系，不应通过增加更多系统来掩盖问题。
