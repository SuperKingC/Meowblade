# 《喵剑奇箱》角色动画系统设计

## 1. 文档信息

- 日期：2026-08-06
- 状态：已确认，待实施
- 适用工程：Unity 2022.3.62f3、UGUI、横屏 16:9
- 角色范围：纸箱侠、小鱼干、毛线球
- 目标场景：战斗界面、编队界面、猫宅主界面

## 2. 背景与已确认决策

工程当前以运行时代码动态创建 UGUI。三名英雄在战斗中由静态 `Image` 表现，`BattleSimulation` 已提供位置、普攻伤害、技能、受击、撤退、胜负和军团号令等逻辑事件，但表现层尚未接入 Animator、Spine 或 Unity 2D 骨骼动画。

最新版三主将外观已保存为 `Assets/Art/art_master_heroes_lineup_v01.png`。该图用作角色外观母图，运行时仍在使用上一版概念图派生的临时 Sprite。

本次已确认采用以下方案：

1. 从最新版三主将母图提取三张独立透明全身 Sprite。
2. 以单张全身 Sprite 配合程序动画和轻量 UGUI 特效完成 Demo 动作，不重新生成逐帧姿势。
3. 新增可复用的代码驱动角色动画状态机，不把动作逻辑直接写进 `BattleScreen`。
4. 战斗单位支持完整动作；主界面、编队界面和战斗 HUD 使用克制的待机或选中反馈。
5. 动画只消费逻辑状态和事件，不参与战斗结算。
6. 不引入 Spine、Tween、粒子系统或其他第三方依赖。

## 3. 目标

### 3.1 功能目标

- 三名英雄均支持 `Idle`、`Move`、`Attack`、`Skill`、`Hit`、`Retreat` 和 `Victory`。
- 三名英雄共用动画系统，但通过角色配置呈现不同的重量、速度、弹性和技能特效。
- 动画与现有 `BattleEvent` 对齐，并兼容 `1x`、`2x` 战斗速度。
- 主界面的对应岗位卡展示英雄轻量待机。
- 编队英雄卡展示轻量待机，选中时播放一次明确但克制的反馈。
- 战斗 HUD 头像只做不影响读数的轻微呼吸。
- 系统边界允许后续复用于军团小猫、敌人和 Boss。

### 3.2 质量目标

- 保持最新版设定图中的轮廓、装备、武器和颜色。
- 动作能区分纸箱侠的重量感、小鱼干的敏捷感和毛线球的柔软法术感。
- 动画不会带动血条、名称或状态文字。
- 快速伤害、状态打断、单位倒下和界面切换不会留下错误变换或残留特效。
- 动画失效不能阻断战斗逻辑或关卡完成。

## 4. 非目标

- 不制作 Spine 工程、Unity 2D 骨骼或分层 PSD/PSB。
- 不补画角色背面、侧面或被装备遮挡的身体部分。
- 不生成逐帧动画序列。
- 不制作小猫、敌人或 Boss 的完整专属动作；本次只保证系统可扩展并维持它们现有表现。
- 不修改战斗伤害、AI、技能数值、冷却、移动速度或胜负规则。
- 不重构现有 `BattleSimulation`、存档或资源生产系统。

## 5. 角色资产处理

### 5.1 输入与输出

输入母图：

```text
Assets/Art/art_master_heroes_lineup_v01.png
```

新增运行时 Sprite：

```text
Assets/Resources/Art/Characters/hero_cardboard_knight_master_v01.png
Assets/Resources/Art/Characters/hero_fish_hunter_master_v01.png
Assets/Resources/Art/Characters/hero_yarn_mage_master_v01.png
```

三个输出必须满足：

- RGBA PNG；
- 完整保留角色身体、尾巴、武器和装备；
- 去除母图奶油色背景及落地阴影；
- 透明边缘无大面积浅色方框；
- 裁切保留适量外边距；
- 统一脚底基准和视觉高度；
- 不覆盖母图或当前临时 Sprite。

现有 `ArtLibrary.HeroSprite(HeroId)` 改为优先加载新版 Sprite。新版资源加载失败时，回退到当前 `hero_*_temp_v01` 资源；两者都缺失时沿用程序化猫咪占位。

### 5.2 导入设置

- Texture Type：Sprite (2D and UI)
- Sprite Mode：Single
- Mipmap：关闭
- Alpha Is Transparency：开启
- Wrap Mode：Clamp
- Filter Mode：Bilinear
- Max Size：不低于 2048
- Mesh Type：Full Rect，避免 UI 裁切和布局差异

## 6. 动画架构

### 6.1 视图层级

战斗单位的稳定定位和动画局部变换必须分层：

```text
UnitRoot                 BattleScreen 控制战场位置
├─ MotionRoot            动画系统控制局部位移、旋转和缩放
│  ├─ CharacterImage     角色 Sprite
│  └─ EffectRoot         角色局部特效锚点
├─ Name
├─ HpBar
├─ ShieldBar
└─ StateText
```

`RefreshUnitViews` 只更新 `UnitRoot.anchoredPosition`、血条和文字。动画系统只修改 `MotionRoot` 及其子节点，因此攻击冲刺、受击和胜利弹跳不会带动 HUD，也不会与战斗位置插值互相覆盖。

### 6.2 核心组件

#### CharacterAnimationController

统一运行时状态机，职责如下：

- 保存动画节点的初始位置、旋转、缩放、颜色和透明度；
- 接收基础状态和一次性动作命令；
- 执行状态优先级、打断、恢复与终止规则；
- 根据 Profile 计算当前帧的局部变换；
- 控制播放速度；
- 在状态结束、禁用或销毁时恢复安全初始值；
- 将视觉特效委托给 `CharacterEffectPlayer`。

控制器不读取或修改 `BattleSimulation`。

#### CharacterAnimationProfile

描述动作差异的只读配置，至少包含：

- 待机周期、呼吸缩放、垂直位移和倾斜；
- 移动周期、弹跳幅度和前倾角度；
- 普攻、技能、受击、撤退和胜利的时长；
- 各动作的位移、旋转、缩放幅度；
- 角色主色、技能色和特效尺寸；
- 角色类型与效果种类。

Profile 由代码注册表按 `HeroId` 或单位类型返回，符合工程当前代码驱动配置模式，不要求新增 Prefab 或 Animator Controller。

#### CharacterAnimationProfiles

提供纸箱侠、小鱼干、毛线球以及通用单位的 Profile。未知角色或配置缺失时返回稳定的通用 Profile。

#### CharacterEffectPlayer

负责护盾环、鱼骨轨迹、毛线范围、受击闪白和军团号令脉冲。它只接收源节点、可选目标节点、效果类型、颜色、时长和播放速度，不接触伤害数据。

#### CharacterEffectPool

复用短生命周期 UGUI 效果节点。对象池具有固定上限，屏幕销毁时清空；池满时允许跳过装饰性效果，不影响角色状态或战斗。

#### BattleAnimationBridge

在 `BattleScreen` 中持有单位 ID 到动画控制器的映射，批量读取当前帧 `BattleEvent`，将逻辑事件翻译为动画命令。桥接层不改变事件内容和顺序，也不向模拟层回写。

#### CharacterPreviewAnimator

复用同一控制器和 Profile，但限制可用状态为 `Idle` 与 `Selected`。用于主界面岗位卡、编队英雄卡和战斗 HUD。

## 7. 状态模型

### 7.1 状态集合

```text
Idle
Move
Attack
Skill
Hit
Retreat
Victory
Down
Selected
```

`Idle` 与 `Move` 是基础循环状态。`Attack`、`Skill`、`Hit` 和 `Selected` 是一次性状态，结束后恢复最新基础状态。`Retreat`、`Down` 和 `Victory` 是终止或战斗结束状态。

### 7.2 优先级

```text
Retreat / Down
> Victory
> Hit
> Skill
> Attack
> Move
> Idle
```

规则如下：

- 高优先级状态可打断低优先级状态。
- 同级一次性动作重新触发时，从开头播放，但高频 `Hit` 需要节流。
- `Skill` 播放期间忽略 `Attack`。
- 进入 `Retreat` 或 `Down` 后忽略后续移动、攻击、技能和受击命令。
- `Victory` 只在战斗完成后进入，不会被普通事件打断。
- 一次性状态完成后，根据最近的单位位移恢复 `Move` 或 `Idle`。

### 7.3 时间与复位

- 战斗动画使用与模拟一致的显示速度，`2x` 时动作与特效同步加速。
- 主界面与编队界面始终以 `1x` 播放。
- 所有变换均从缓存初始值和当前归一化时间计算，不在上一帧结果上累计。
- 状态切换、禁用、界面销毁或异常恢复时重置全部受控属性。

## 8. 三名英雄的动作语言

| 状态 | 纸箱侠 | 小鱼干 | 毛线球 |
| --- | --- | --- | --- |
| Idle | 稳重呼吸、身体轻压、盾牌微沉 | 警觉地左右换重心，节奏短而快 | 柔软上下漂浮，身体与法杖轻摆 |
| Move | 沉重踏步和较低频下压 | 前倾快速弹跳，三者中速度感最强 | 短步摇摆，带轻微软弹感 |
| Attack | 短蓄力后向前重击，随后明显后坐 | 快速前探并投出鱼骨轨迹 | 法杖上扬并释放紫色法术脉冲 |
| Skill | 举盾、身体放大、金色护盾环扩散 | 连续两次投掷，产生两条错开的鱼骨弧线 | 短暂蓄力，紫色毛线环在目标区域扩张 |
| Hit | 小幅后仰，保持重甲稳定感 | 快速后退并短促旋转 | 明显挤压后回弹 |
| Retreat | 单膝下沉后淡出 | 后跳并快速淡出 | 缩成一团、下沉淡出 |
| Victory | 举剑和盾牌，进行两次有重量的弹跳 | 快速左右庆祝跳 | 摆动法杖并连续软弹跳 |

动作只通过整张 Sprite 的变换和附加特效表达，不声称独立移动原图中无法拆分的武器、手臂、耳朵或尾巴。

## 9. 战斗事件映射

`BattleAnimationBridge` 每次先取得完整事件批次，再执行以下步骤：

1. 收集批次中的 `Skill` 来源单位 ID。
2. 处理 `Damage`：目标播放 `Hit` 和受击反馈；只有不在技能来源集合中的攻击者才播放 `Attack`。
3. 处理 `Skill`：来源播放角色专属 `Skill`，目标存在时将效果锚定到目标或目标区域。
4. 处理 `UnitDown`：英雄与小猫进入 `Retreat`，敌人进入较短的 `Down`。
5. 处理 `Command`：所有存活我方单位短暂下压并显示蓝色纸箱护盾脉冲。
6. 处理战斗结束消息：胜利时存活英雄进入 `Victory`；失败时保留已经发生的撤退结果并停止普通循环。

移动状态不依赖事件。桥接层比较单位上一帧和当前帧的映射位置；位移超过小阈值时设置基础状态为 `Move`，否则设置为 `Idle`。该判断只影响表现，不改变单位位置。

如果技能事件没有有效目标，角色仍播放本地技能动作；飞行或区域效果降级为角色周围脉冲。伤害数字保持现有逐条显示规则，不因受击动画合并而丢失。

## 10. 各界面接入

### 10.1 战斗界面

- 三名英雄使用完整状态机和专属效果。
- `UnitRoot` 继续由现有位置映射和插值控制。
- 角色倒下后的透明度由终止动画控制，`RefreshUnitViews` 不再每帧覆盖该透明度。
- 战斗结果弹窗延迟需要容纳短胜利或撤退动作，同时不得延迟逻辑结算。

### 10.2 主界面

- 三个岗位卡分别展示对应英雄的小型全身 Sprite：纸板岗位对应纸箱侠，鱼干岗位对应小鱼干，零件岗位对应毛线球。
- 角色放置在岗位卡已有图像区域的安全位置，不能覆盖岗位名称、速率、状态、进度条或按钮点击区。
- 三个 Profile 使用不同起始相位，避免待机动作完全同步。
- 主界面只播放 `Idle`，不生成战斗特效。

### 10.3 编队界面

- 三张英雄卡使用新版角色 Sprite 并持续播放轻量 `Idle`。
- 选择英雄时播放一次 `Selected` 弹跳和角色色高亮脉冲。
- 待机与选中反馈不得改变按钮 RectTransform 或阻塞射线检测。

### 10.4 战斗 HUD

- 头像保留现有布局，只进行幅度极小的呼吸缩放。
- HUD 不播放攻击、技能、受击或撤退动作，保证 HP、护盾和小猫数量易读。

## 11. 异常处理与清理

- Sprite 缺失：新版资源到临时资源再到程序占位，逐级降级。
- Profile 缺失：使用通用 Profile 并记录一次警告。
- 目标缺失或已撤退：取消目标型飞行，改播本地脉冲或跳过装饰效果。
- 密集受击：短窗口内合并闪白和抖动，仍保留所有伤害数字。
- 非法或无法恢复的状态：记录一次包含角色与状态的警告，复位并回到 `Idle`。
- UnitDown：立即进入终止状态，并拒绝后续普通命令。
- 屏幕销毁：动画控制器、效果节点、对象池和映射随根节点销毁，不保留协程或静态场景引用。
- 动画组件异常：不得向上抛出并中断 `BattleScreen.Tick`；动画可降级为静态表现。

## 12. 性能约束

- 目标同屏上限沿用工程规范：20 个单位。
- 动画 Tick 不创建临时列表、材质或纹理。
- 事件批次可复用现有列表；效果节点通过固定上限对象池复用。
- 所有角色共用 UGUI 默认材质，受击通过 `Image.color` 和附加效果节点表现。
- 不可见屏幕不运行角色动画。
- 对象池耗尽时优先丢弃装饰性效果，不允许阻塞战斗或无限扩容。

## 14. 验收标准

1. 三名英雄使用最新版设定造型，轮廓、武器、装备和颜色与母图一致。
2. 战斗中能清楚辨认三者不同的待机、移动、普攻、技能、受击、撤退和胜利表现。
3. 普攻、技能和受击与现有战斗事件对应，技能伤害不会额外播放普通攻击。
4. 动画不修改战斗数值、单位逻辑位置或胜负结果。
5. `1x` 与 `2x` 下节奏正确；快速连续伤害不会卡住状态或遗留特效。
6. 主界面岗位卡和编队英雄卡持续播放轻量待机，不遮挡内容或阻塞交互。
7. 胜利、失败、主动撤退、角色倒下和界面切换均正确清理动画状态。
8. 新版资源失败时能够降级，动画系统失败时战斗仍可继续。
9. Unity 编译、自检、两场战斗流程和视觉截图验证全部通过。
